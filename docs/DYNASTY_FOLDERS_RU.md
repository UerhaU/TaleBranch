# Папки династий в веб-версии

Реализовано 16 октября 2026 года, порядок создания уточнён владельцем 17 октября. Пользователь выбирает место сохранения; приложение создаёт в нём папку династии. При открытии существующей династии приложение работает с её папкой на месте.

## Создание

1. Нажмите «Новая династия» и укажите название.
2. Нажмите «Выбрать место сохранения». В системном диалоге выберите место на нужном диске, например `D:\Династии`. В нём могут находиться любые другие файлы и папки.
3. Нажмите «Создать». Кнопка доступна, когда указано название и выбрана папка. Она использует уже выбранную папку и не открывает окно выбора повторно.

Название и папку можно указать в любом порядке: выбор папки сохраняется при редактировании названия. Если повторно открыть выбор папки и отменить его, прежняя выбранная папка останется.

Приложение само создаёт внутри выбранного места папку с названием династии и записывает в неё `dynasty.json`. Например, для «Дом Вороновых» получится `D:\Династии\Дом Вороновых\dynasty.json`. Если имя занято файлом или папкой, будет выбрано свободное: «Дом Вороновых (2)», «Дом Вороновых (3)» и так далее. Существующие записи и их содержимое сохраняются. Недопустимые в Windows символы заменяются только в имени папки; название самой династии не меняется. Отмена выбора или создания не создаёт запись в браузере.

## Открытие существующей династии

Нажмите «Открыть папку династии» и выберите папку, содержащую `dynasty.json`. Сохраняются исходные идентификаторы и название; копия в служебном каталоге или в localStorage не создаётся. Последующие изменения записываются в этот же файл.

При первом запуске показывается начальный экран с кнопками создания, открытия и импорта; форма создания автоматически не открывается. При следующем запуске приложение открывает последнюю династию из исходной папки. В настольном варианте ссылка хранится отдельно от сохранений: `TaleBranch-data/last-folder.json` рядом с `.exe` содержит путь и название, без персонажей и фотографий. Список недавних хранится отдельно в `recent-folders.json`.

В веб-версии для восстановления используются сохранённая ссылка на папку в IndexedDB и настройка последней папки. Автооткрытие выполняется только при уже выданном разрешении, без диалогов при запуске. Если доступ нужно подтвердить заново, папка перемещена или файл повреждён, остаётся начальный экран. Недавние папки доступны на нём и в меню названия династии. Вместо недоступной папки прежняя браузерная копия автоматически не открывается.

«Закрыть династию» сначала сохраняет текущие изменения, затем возвращает начальный экран и очищает ссылку для автооткрытия. Закрытие самого приложения сохраняет эту ссылку. Файлы остаются на месте.

## Прежние данные

- Династии старой веб-версии доступны в разделе «Ранее сохранённые в браузере». Откройте нужную и в меню названия выберите «Сохранить в выбранную папку». После успешной записи приложение переключится на эту папку. Старая запись браузера сохраняется; её можно удалить отдельно.
- Перенос сохраняет текущее состояние, включая ещё не сохранённые изменения. Он доступен и при переполненном хранилище браузера: запись старой браузерной копии для такого переноса не требуется.
- Кнопка «Импортировать» принимает прежний экспорт `.dynasty-tree` или JSON с тем же манифестом. После проверки файла выберите место сохранения: приложение создаст там отдельную папку импортированной династии. Дальнейшие изменения сохраняются в неё. Исходный экспорт остаётся на месте.
- Для повторного открытия уже подготовленной папки используйте открытие папки, а не импорт экспортного файла.

## Что хранится на диске

```text
Выбранная пользователем папка/
  Дом Вороновых/
    dynasty.json
    photos/
      3f2a…c9.jpg
```

`dynasty.json` содержит данные династии, карточки, родство, личные отношения, координаты и корзину. Фотографии лежат отдельными файлами в `photos/`: каждый исходный снимок хранится один раз, файл назван по SHA-256 его содержимого. В `dynasty.json` у фото записаны только имя файла и настройки кадрирования; кадр рисуется заново при показе. Манифест содержит версию формата (`2`, если есть фото; `1` без фото) и контрольную сумму SHA-256. Каталог игровых справочников остаётся общим ресурсом приложения.

Старая династия, где фото лежали внутри `dynasty.json` (оригинал и кадр), переносится автоматически при открытии. Перед переносом рядом сохраняется копия старого файла `dynasty.backup-before-photos.json`; уже существующая копия не заменяется. Приложение удаляет из `photos/` только свои файлы (имя из 64 шестнадцатеричных символов), на которые больше нет ссылок; другие файлы в этой папке не трогаются. Если файл фото удалён вручную, династия всё равно открывается, пропадает только это фото.

Экспорт `.dynasty-tree` остаётся одним файлом: в нём есть все исходные снимки и настройки кадрирования. Импорт восстанавливает фото; старые файлы экспорта тоже открываются.

В профиле браузера сохраняются только настройки и ссылки-разрешения на папки с названиями для списка недавних. Старые династии из localStorage не удаляются автоматически. Поэтому выбор папки на D: определяет место хранения новой династии, но не переносит профиль браузера и системные кеши с C:.

Браузер не сообщает приложению абсолютный путь к папке. Полный путь пользователь видит в системном диалоге; в приложении отображается имя выбранной папки и `dynasty.json`.

## Автосохранение и удаление

Автосохранение выполняется после изменения с короткой задержкой. Ctrl+S принудительно записывает изменения. При ошибке данные остаются в открытом окне; доступны повторное сохранение и экспорт. Не закрывайте вкладку, пока нужные изменения не сохранены.

Запись заменяет предыдущий файл только после успешного завершения потока. Сохранения одной сессии идут последовательно. При наличии Web Locks записи разных вкладок приложения координируются. Проверка содержимого файла до записи и перед её завершением обнаруживает внешние изменения и останавливает перезапись. Это не система совместного редактирования: при конфликте экспортируйте текущий вариант и повторно откройте папку для сравнения.

Безвозвратное удаление персонажей сохраняет результат в исходном файле и очищает историю отмены. Подтверждённое удаление всей династии удаляет её папку целиком, включая `dynasty.json`, вложенные папки, фотографии и любые другие файлы внутри. Об этом явно сообщает подтверждение. Родительская папка и соседние файлы сохраняются; ссылка для автооткрытия и запись в недавних очищаются.

Нативное удаление проверяет выбранный абсолютный путь, актуальность файла и блокировку другим процессом; корень диска и каталог, содержащий настройки приложения, удалять нельзя. В браузере для удаления папки целиком требуется сохранённый доступ к её родительской папке (сохраняется при создании) либо поддержка удаления самой папки браузером. Если ни того ни другого нет, операция завершается ошибкой без удаления одного лишь JSON. Экспортные копии за пределами папки династии и прежние записи браузера сохраняются отдельно.

## Ограничения веб-версии

Для выбора папок нужен File System Access API. Используйте Chrome или Edge и `http://localhost:1420/`; браузер запросит доступ к выбранной папке. При отсутствии API приложение показывает пояснение, не подменяя запись в папку скрытым сохранением в браузере. Справка API: [документация Chrome](https://developer.chrome.com/docs/capabilities/web-apis/file-system-access).

Результаты проверок вынесены в [отдельный отчёт](BETA_VERIFICATION_RU.md).
